# Moving structure research

Research snapshots inspected for the planned movement system; no source or assets from these projects have been copied into this mod. License conclusions below are for the inspected snapshots and must be rechecked for each file before any future port, including headers and third-party attribution.

- Create `mc1.21.1/dev`, commit `9f01ec4b072e35d202e7e29f5ecd7c461815892f`: root LICENSE.md licenses code under MIT (copyright The Create Team / The Creators of Create), but reserves rights to assets under `src/main/resources/assets/`. `ContraptionCollider` transforms entities and relative motion into contraption space, tests nearby block collision shapes using `ContinuousOBBCollider`, resolves against world collision, and applies contact-point motion. `ControlledContraptionEntity` delegates controlled movement to its controller; the collision system depends on substantial Create and Catnip infrastructure. `ElevatorContactBlockEntity` persists names and column state, and notifies the column when names change. `AbstractPulleyRenderer` renders repeated rope pieces based on partial-tick offset and samples lighting per segment. The current local rope renderer already repeats segments but has only a static integer attachment position.
- Sliding-Platforms, commit `d6a5686328035de98e05bd0cce4b60039ad96b27`: root MIT license, copyright 2026 Handmade. `SlidingPlatformEntity` advances server position using an eased step, sends state, and keeps previous/current client positions for render interpolation. `PlatformCollisionHandler` handles overlapping entities and pushes them with platform motion. Its Minecraft mappings and framework differ from this project, and its approach needs dedicated-server and edge-case evaluation before adaptation.
- ThutTech, commit `f7a04b29c34ef05192adf056f2d691f07eb0461f`: root MIT license, copyright 2020 Thuts-Mods. `EntityLift` keeps floor heights and a destination, saves floor data and calculates lift motion; it relies on ThutCore and older Minecraft APIs.
- ThutCore, commit `c14f0185b239801cf60ff0fa831bd1a64eafe6bb`: root MIT license, copyright 2020 Thuts-Mods. `BlockEntityBase`, `BlockEntityUpdater`, and the block-entity world implement moving block storage, collision and a virtual world; this is a broad older framework rather than a small drop-in solution.

For a future implementation, start from a server-authoritative vertical-only entity with a persisted local block snapshot, swept collision against individual cabin shapes and world obstructions, rider contact motion, synchronized previous/current positions and partial-tick rendering. Assembly and restoration must first have a crash-safe ownership protocol; a stored snapshot alone does not prevent duplication. The design must handle chunk unloading, disconnect/reconnect and dedicated-server player movement validation. Create's collision path is the priority reference, but porting only an isolated method without its surrounding synchronization and collision assumptions would be unsafe. Evaluate the exact dependency and notice requirements when selecting source to port.
